# repro-fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CLI that takes a plain-English bug report, reproduces it as a failing Kane CLI browser test, has Claude Code fix the code, and re-runs the frozen test until it passes.

**Architecture:** A deterministic state machine (`loop.ts`) calls two injected adapters: `kane.ts` (spawns `kane-cli run --agent --headless`, parses NDJSON `run_end`) and `claude.ts` (spawns `claude -p --output-format json`). Store/report modules write `.repro/tests` and `.repro/reports`. A Vite + React demo shop with planted bugs is the showcase target.

**Tech Stack:** Node 26, TypeScript 5, tsx (run), vitest (tests), no runtime deps beyond Node stdlib for the CLI; Vite + React for the demo.

**Spec:** `docs/superpowers/specs/2026-11-24-repro-fix-design.md`

## Global Constraints

- Agent = Claude Code headless (`claude -p`), never the Anthropic API/SDK. No API key anywhere.
- Kane exit codes: 0 = passed, 1 = failed, anything else (or no `run_end`) = `infra_error`, which never counts as reproduced.
- Caps: 2 objective retries (3 objective attempts total), 3 fix attempts total (regression fixes count against them).
- The objective is frozen after reproduction; the green run uses the identical string.
- Fix step must not modify `.repro/`; `disallowedTools` `Edit(.repro/**)`, `Write(.repro/**)` plus a hash check that aborts on change.
- CLI never pushes; it commits locally on branch `repro-fix/<slug>` only if target is a git repo with a clean tree.
- Windows first: spawn `kane-cli`/`claude` with `shell: true`-safe quoting (pass the objective through a temp file or properly escaped arg — see Task 2).
- No reference to the user's YouTube channels anywhere in repo, demo data, or launch docs.
- Default model alias `sonnet`; `--model` overrides.

## Review Focus

1. Objective strings containing quotes/apostrophes (e.g. `the 'Apply' button`) on Windows `cmd` shims — must reach Kane intact. Test in Task 2.
2. Kane stdout containing non-JSON lines or a truncated stream with no `run_end` — must become `infra_error`, not a crash. Test in Task 2.
3. `claude -p` final text with prose or ```json fences around the JSON — must still parse; total garbage → clear error. Test in Task 3.
4. Target URL not up and no `start` command — fail fast with a readable message before spending credits. Test in Task 7.
5. Target git tree dirty — skip commit with a warning, never stash/reset user work. Test in Task 6.

### Task 5: The loop

**Produces:**

```ts
export interface LoopResult { status: LoopStatus; bug: string; objective?: string; attempts: Attempt[]; credits: number; changedFiles: string[] }
export interface LoopDeps { kane: RunKane; claude: RunClaude; cwd: string; url: string;
  savedTests: { name: string; objective: string }[]; log: (event: string, detail?: string) => void; model?: string }
export function runLoop(bug: string, deps: LoopDeps): Promise<LoopResult>;
```
- [ ] **Step 1: Tests with fake kane/claude** —
  - `fail→fix→pass ⇒ verified`, objective identical in reproduce and verify attempts.
  - `passes 3× ⇒ not_reproduced`, claude never called in edit mode.
  - `infra_error twice on reproduce ⇒ infra_error`, no fix call.
  - `fail, fix, fail, fix, fail, fix, fail ⇒ not_verified` after exactly 3 fixes.
  - `verify passes but saved test fails ⇒ fix gets regression failure; then all pass ⇒ verified`.
  - `fake fix writes into .repro ⇒ tampered`, loop stops.
  - `credits` summed across all Kane calls.
- [ ] **Step 2:** FAIL. **Step 3:** Implement per spec "The loop" steps 1–4. Infra error during verify: retry once without consuming a fix attempt. **Step 4:** PASS. **Step 5:** Commit `feat: reproduce-fix-verify loop`.
